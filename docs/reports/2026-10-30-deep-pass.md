The paid run is complete and published in `docs/reports/2026-10-30-deep-pass/run/`. The sections from "Before the run" down are the
report as written on 10-30, before any paid call, and are kept as they were.

## What is built, before any call

- **The rule:** `docs/proposals/vote-single-v1.md`. A first vote of natural at 0.85 or more lowers alone. Natural from 0.70
  to under 0.85 earns two more votes, then the rule of record decides. Anything else keeps the grade. The thresholds were set
  on 9c's votes with the pieces in view, on 18 votes on piece ids, and the proposal says what that costs.
- **The cumulative dollar cap:** in the ledger, 120 USD over every run on the new `docs/reports/ledgers.json`. An environment
  variable can lower it and cannot raise it. A listed ledger that has gone missing stops everything, and a test fails if a
  published ledger is not listed.
- **The stop after 100 calls:** in the ledger. The run writes `CHECKPOINT.json` and goes on only with `--billing-usd`, the
  figure a person read from the Billing page, which goes in that file.
- **Votes reserved per strip:** the reviews run only after every vote. One vote per candidate is also reserved on the ledger
  before anything is sent, and calls outside the vote stage cannot spend it.
- **Spark:** asked for every verdict in one turn after its fetches, and with two turns left it is told which candidates have
  none. Fake-backend tests cover the loop, but only a real run can show that Spark does what it is told.
- **Saturated pixels drawn bright:** `saturated_old_new.png` shows one real crop old and new; the black patches inside the
  bright object are gone. It matters unevenly. 75 of 100 crops on `ESP_025815_1655` have a saturated pixel in the central 64
  px, 17 on `ESP_022038_1995`, and 0 to 6 on the other ten (`dry_check.json`). So 9c's vote behaviour transfers least to those
  two strips.
- **The old paths are unchanged:** the new drawing, rule and prompt are all off by default, so earlier requests hash as before.

- **Nothing identifying in a prompt.** 1,373 request files were scanned again after the leak guard: 0 observation ids, dates,

- **An exported crop is the strip.** 36 of 36 sampled crops have the same pixels from the export and from the strip.
- **The scoreboard reproduces item 13.** The summary script gives frozen-v1 8 of 32 on the key and 15 of 128 on transplant

## What I decided and why

- **Top 100, with `--max-usd 36`.** Above that the price leaves the plan's target.
- **Transplant board included.** The plan asks every v2 item for every board. I vote on the union of each fold's top 100, 128
  detections, about 3 USD. A detection near a tile's edge shows black past the edge, which native crops rarely do, so a vote
  could read that as a difference between the boards.
- **The review covers the top 20 left after the votes,** not the top 100. A review of 100 records would cost far more per turn,
  and the plan's question is about the top 20.
- **`more_votes` is the only check.** A zoom pass needs SAM, which is outside this item, and a 512 px crop, which is larger
  than the export.
- **The recognition probe stops nothing.** It runs again because the crops changed. A yes is reported and the votes are read in
  that light. Item 9d's stop rule was about examples, and this item has none.
- **Caps, in `out/caps.env` (not committed):** Wonder 2,600, Spark 72, SAM 0. These are for you to approve with the spend.

## Things that went differently from plan

- Two of my commands were refused by the permission layer: one too long to parse and one heredoc. I made those edits with the
  Edit tool and read those files with the Read tool, and nothing was skipped.
- 1,394 calls wrote 1,373 request files, because an identical request has one file. 11 of the 21 are Spark's first turn, which
  is the same text on every strip. I expect the other 10 are candidates with identical crops, but did not trace them. In a real
  run a repeat replays from the recording at no cost and the ledger still counts it, so the ledger overstates slightly.
- `ruff check` flags long lines in the new files, as it does for the other recent ones. Tests and the leak check are green.

## To run it

In a window with `MODEL_API_KEY` and `LANDERS_REAL_CALLS=1` exported:

    uv run --env-file out/caps.env experiments/deep14_run.py --reference ESP_025815_1655 --reference-for-reference ESP_030313_1755 --probe ESP_030313_1755:3 ESP_017716_2485:3 --backend real --out-dir out/deep14

It stops after 100 calls, as the Decisions of 10-30 10:29 require. Compare the ledger with the Billing page, then add
`--billing-usd X` to the same command. A rerun skips what is written. When it finishes:

    uv run experiments/deep14_summary.py --run out/deep14 --no-texture PSP_004336_1035 PSP_004402_1030
    uv run scripts/models_publish.py out/deep14 docs/reports/2026-10-30-deep-pass/run

After publishing, point the register's item 14 row at the published ledger. The inputs are in this worktree only, under `out/deep14/inputs/`;
`deep14_inputs.py` rebuilds them in a few minutes.
